Redaction that shows its work.

Inkguard redacts patient identifiers from typed clinical documents on your own computer, keeps the clinical detail a study needs, and writes an audit trail for every run. Free and open source, for research teams.

  • Offline. Its own code sends nothing anywhere, and a test runs the engine with the network switched off to make sure.
  • Built for the HIPAA Safe Harbor method. Looks for the identifiers it lists, including in document properties, comments, tracked changes, headers, hidden sheets and file names.
  • Honest about its limits. It finds most identifiers, not all. Every output is reviewed by a person, and every miss we know of is published.

How it works

Point it at a folder of Word, text-based PDF, Excel, CSV or plain-text files. It redacts copies; your originals are only read. Each patient's notes are read together, so a name confirmed in one note is also removed from the others. Every file comes out in one of three folders.

1_REDACTED-NO-FLAGS

Redacted, no flags

Every word left in was one the tool could account for. Pending human review.

2_REDACTED-FLAGGED

Redacted, words to check

Uncertain words listed with their line numbers, so a reviewer goes straight to them.

3_NOT-PROCESSED-MAY-CONTAIN-PHI

Not processed

Exact copies of photos, scans, other formats and files it stopped on as a precaution. Treat as PHI.

An audit trail for every run

A PDF recording who ran it, on what, with which version, and every file by id. Designed to hold no text from your files.

Citations ready to paste

APA, AMA, Vancouver, BibTeX and a Methods paragraph, written into every results folder.

Keeps the medicine

Kerrison, Mayfield, Lenke 1A, Hunt and Hess 2, 12 cmH2O: kept. A patient who shares a surname with a sign is still a person, and is still redacted.

Hidden content too

Document properties, comments, tracked changes, headers, hidden sheets and file names are checked, not just the visible page.

What it still misses, and how to check the numbers yourself

The test notes are AI-generated synthetic data. The benchmarks and the engine were written with the same AI assistant and may share blind spots. Known misses in 0.25.0 include surnames that are also ordinary words and towns absent from the place list; the full list is in benchmark/RESULTS.md.

Every number can be rerun. Each audit trail carries a fingerprint of the exact code that produced it, so a result in a paper can be traced to its version and checked later.

git clone https://github.com/inkguard-app/inkguard
inkguard --self-test                              # one minute, network blocked
./tools/run_tests.sh all                          # about 1,000 tests
python tools/eval_corpus.py --half held-out       # score the benchmark

Get started

Python 3.11–3.14 on a 64-bit computer with 4 GB of memory and about 1 GB of disk. Installation downloads about 600 MB of libraries once; after that Inkguard runs offline. PDFs need Tesseract OCR.

git clone https://github.com/inkguard-app/inkguard.git
cd inkguard
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m pip install --no-deps .
inkguard --self-test

  1. Try it first on the invented notes in examples/sample-notes, or preview a real run with --dry-run, which writes nothing.

  2. Run inkguard NOTES_FOLDER -o RESULTS_FOLDER, or open the window with inkguard-window: welcome, set up, working, done.

  3. Read 0_READ_ME_FIRST_(Guide).txt in the results folder, then review every file before any of it is used or shared. Keep the results on an encrypted disk.

Release downloads come with SHA256SUMS.txt so you can confirm the file you have is the file that was published.

An open invitation

Inkguard is an independent, non-commercial project by a medical student. It is at the stage where it needs other people: to test it, to break it, and to validate it on real records under the proper approvals. If any of this is your field, please write.

Clinical informatics and de-identification researchers

Compare it with your own tools on your own synthetic notes, or help design a validation study on real records under an IRB. Co-authorship is on the table.

Research teams

Try it on invented notes in your own specialty and tell us what it misses or over-redacts. Every run writes a feedback report that holds counts and codes only, never your text.

Privacy and security people

Read the threat model and the security controls, each with its test, and tell us where they fall short.

Developers

The code is Apache 2.0 and open to inspection. Pull requests open once the preview settles; bug reports with invented examples are welcome now.

inkguard.project@gmail.com

What it is not

  • Not validated on real clinical records yet. This is a public preview.
  • Not a replacement for review. No automated tool catches everything.
  • Not an Expert Determination, not legal advice, not a certification and not a medical device.
  • Typed English text only. Photos, scans and audio are set aside and listed.
  • Not affiliated with any university, medical school or hospital.

Inkguard is an automated tool. It can make mistakes, including misreading context. A person must check every output before it is used.

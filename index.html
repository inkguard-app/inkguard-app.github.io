Inkguard

Research software that helps redact patient identifiers from typed clinical documents before they are used in research. Version 0.25.0, public preview, 19 October 2026.

Purpose and scope

Inkguard is a small piece of research software. Its only purpose is to assist and speed up one step of clinical research: removing patient identifiers from typed documents, such as clinic notes, letters and spreadsheets, before those documents are reviewed and used in a study that has the approvals it needs. The software does a first pass. A person then checks every file, and the researcher's institution decides whether the result is de-identified.

It is not a product, a service or a clinical tool. It is not sold, it is not supported commercially, and nothing is offered with it. It is not for patient care, billing, legal disclosure or any decision about a patient. It is meant to be used only for research, under the approvals the user's institution requires, such as an IRB or ethics board and any data agreements. It is free and open source under the Apache License 2.0.

Status

Everything on this page describes version 0.25.0, a public preview released on 19 October 2026. It is an early version with known gaps, and work on it continues. It has not been validated on real clinical records; that would need a research partner with the proper approvals.

Known misses in this version include surnames that are also ordinary words and towns that are not in its place list. The full list of measured misses, by type, is in the published results.

If a run is interrupted, full copies of the original files stay in a hidden .inkguard folder inside the results folder until the user runs again into that folder or deletes the whole results folder. Reading PDFs also uses the computer's temporary folder briefly. Inputs and results should be stored on an encrypted disk and outside cloud-synced folders.

Changes are announced only when they are released, in the changelog, each with its own version number and DOI. No release dates are promised.

What it does

Inkguard reads Word, text-based PDF, Excel, CSV and plain-text files on the user's own computer. After installation its own code opens no network connections. It looks for the identifiers listed by the HIPAA Safe Harbor method that can appear in typed text, which are 16 of the 18 kinds, both in the visible text and in document properties, comments, tracked changes, headers, hidden sheets and file names.

It reads each patient's notes together, so that a name confirmed in one note is also redacted in the others. It writes redacted copies and only reads the originals. Every file it receives is sorted into one of three folders: redacted with no flags, redacted with words to check, or not processed. A file with no flags can still contain identifiers, which is why every file is reviewed. Eponyms, instruments, scales and doses, such as Kerrison, Lenke 1A or 12 cmH2O, are not treated as identifiers, to limit over-redaction.

Each run on the user's computer produces its own reports in the results folder: an audit trail PDF, citations with a draft Methods paragraph, and a feedback report designed to hold counts and codes only.

Test results

The figures below are for version 0.25.0, the software alone, before any human review. Each test set was split in half. The software was tuned on one half and scored on the other half, which was set aside and not used for tuning. The test notes are AI-generated synthetic data, and the benchmarks and the software were written with the same AI assistant, so they may share blind spots.

On the held-out half of a set of deliberately difficult synthetic notes (72 patients, 289 notes), the software redacted 90.5% of the identifiers Safe Harbor requires (95% confidence interval 89.1–91.7%). That figure is measured on the 258 notes it released. A further 31 notes, holding 13.9% of the identifiers, were held back unredacted for a person. Of the 34 notes it sorted into the no-flags folder, 10 still held at least one identifier.

On the held-out half of a clinical-preservation set (20 patients, 58 notes), it redacted 97.9% of identifiers (95% CI 96.2–99.4%) and left 98.1% of marked clinical phrases unredacted (95% CI 97.1–99.1%). On the held-out half of ASQ-PHI, a published benchmark, it redacted 97.1% of identifiers.

These figures describe these test sets only. They are not a prediction of performance on real records.

Methods, data and misses by type are in benchmark/RESULTS.md.

Installation

Python 3.11–3.14 (tested on 3.11 and 3.13), a 64-bit computer, 4 GB of memory and about 1 GB of disk. Installation downloads about 600 MB of libraries once. PDFs need Tesseract OCR. Full instructions are in the README.

git clone https://github.com/inkguard-app/inkguard.git
cd inkguard
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m pip install --no-deps .
inkguard --self-test

Use it on patient records only with your institution's approval, on a computer and encrypted storage approved for patient information, outside cloud-synced folders.
